│                                                                                                                                                                              │
│  ---                                                                                                                                                                         │
│                                                                                                                                                                              │
│  ### 5 Key Facts                                                                                                                                                             │
│                                                                                                                                                                              │
│  - **Hybrid Architecture** – RAG combines a **retriever** (often a dense vector search over a large external knowledge base) with a **generator** (typically a large         │
│  language model). The retriever supplies relevant documents or passages, and the generator conditions its output on that retrieved context.                                  │
│                                                                                                                                                                              │
│  - **Improved Factual Accuracy** – Empirical studies (e.g., Lewis et al., 2020; Izacard & Grave, 2022) show that grounding generation in retrieved evidence reduces          │
│  hallucinations and yields higher scores on factual QA benchmarks (e.g., Natural Questions, TriviaQA).                                                                       │
│                                                                                                                                                                              │
│  - **Scalable Knowledge Updates** – Because the knowledge source is external, updating facts does **not** require re‑training the language model. Adding or editing          │
│  documents in the index instantly changes the information the system can cite.                                                                                               │
│                                                                                                                                                                              │
│  - **Two Main Retrieval Paradigms** –                                                                                                                                        │
│    1. **Sparse retrieval** (BM25, Elasticsearch) leverages term‑frequency statistics and works well for exact keyword matches.                                               │
│    2. **Dense retrieval** (bi‑encoders like DPR, ColBERT, or newer contrastive models) encodes queries and passages into a shared vector space, enabling semantic matching   │
│  beyond lexical overlap.                                                                                                                                                     │
│                                                                                                                                                                              │
│  - **Prompt‑Engineering & Fusion Strategies** – The way retrieved texts are incorporated matters. Common techniques include:                                                 │
│    - **Concatenation** of top‑k passages to the prompt.                                                                                                                      │
│    - **Fusion‑in‑decoder** (e.g., Fusion-in-Decoder, FiD) where each passage is encoded separately and combined inside the decoder.                                          │
│    - **Reranking** or **knowledge‑aware attention** to weight more relevant snippets during generation.                                                                      │
│                                                                                                                                                                              │
│  ---                                                                                                                                                                         │
│                                                                                                                                                                              │
│  ### 2 Open Questions                                                                                                                                                        │
│                                                                                                                                                                              │
│  - **How to Optimize Retrieval‑Generation Interaction at Scale?**                                                                                                            │
│    While dense retrievers provide semantic relevance, they can return noisy or overly long passages that overwhelm the generator’s context window. What principled methods   │
│  (e.g., adaptive k‑selection, learned passage summarization, or dynamic context windows) can balance relevance, brevity, and computational cost for real‑time, large‑scale   │
│  deployments?                                                                                                                                                                │
│                                                                                                                                                                              │
│  - **Evaluation of Trustworthiness Beyond Accuracy**                                                                                                                         │
│    Current metrics focus on factual correctness (e.g., exact match, F1). However, users also care about **source attribution**, **bias mitigation**, and                     │
│  **explainability**. How should we design evaluation frameworks that capture these dimensions—such as measuring citation fidelity, provenance tracking, or user‑perceived    │
│  trust—in a way that guides the development of more responsible RAG systems?                                                                                                 │

**Retrieval‑Augmented Generation (RAG): Key Facts & Open Questions**

---

### 5 Key Facts  

- **Hybrid architecture** – RAG pairs a **retriever** (usually a dense vector search over an external knowledge base) with a **generator** (typically a large language model). The retriever returns relevant documents or passages; the generator conditions its output on that retrieved context.  

- **Improved factual accuracy** – Grounding generation in retrieved evidence reduces hallucinations and boosts scores on factual QA benchmarks such as Natural Questions and TriviaQA (Lewis et al., 2020; Izacard & Grave, 2022).  

- **Scalable knowledge updates** – Because the knowledge source is external, facts can be added or edited in the index without re‑training the language model [source needed].  

- **Two main retrieval paradigms** –  
  1. **Sparse retrieval** (e.g., BM25, Elasticsearch) relies on term‑frequency statistics and excels at exact keyword matches.  
  2. **Dense retrieval** (bi‑encoders such as DPR, ColBERT, or newer contrastive models) maps queries and passages into a shared vector space, enabling semantic matching beyond lexical overlap.  

- **Prompt‑engineering & fusion strategies** – How retrieved texts are fed to the generator matters. Common approaches include:  
  - **Concatenation** of the top‑k passages to the prompt.  
  - **Fusion‑in‑decoder** (e.g., Fusion‑in‑Decoder, FiD), where each passage is encoded separately and merged inside the decoder.  
  - **Reranking** or **knowledge‑aware attention** to weight the most relevant snippets during generation.  

---

### 2 Open Questions  

- **Optimising retrieval‑generation interaction at scale** – Dense retrievers can return noisy or overly long passages that exceed the generator’s context window. What principled methods (e.g., adaptive k‑selection, learned passage summarisation, dynamic context windows) can balance relevance, brevity, and computational cost for real‑time, large‑scale deployments?  

- **Evaluating trustworthiness beyond accuracy** – Current metrics focus on factual correctness (exact match, F1). Users also care about **source attribution**, **bias mitigation**, and **explainability**. How should we design evaluation frameworks that capture these dimensions—such as citation fidelity, provenance tracking, or user‑perceived trust—to guide the development of more responsible RAG systems?
